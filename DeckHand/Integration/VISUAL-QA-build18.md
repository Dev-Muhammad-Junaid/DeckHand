## How these were captured (re-check with the same tests)

- New XCUITest target `PixelHandUITests` (`DeckHand/PixelHandUITests/PixelHandUITests.swift`, scheme DeckHandiOS): 12 walks (onboarding, landscape onboarding, picker, pointer and keyboard, deck, screen/mirror/PiP, Ask, capture, Settings, My Macs, landscape shell, free plan and paywall). Each step is an `XCTAttachment` and, with `TEST_RUNNER_PH_QA_OUT=<dir>` in xcodebuild's environment, a PNG in `<dir>/<device>-<tag>/<test>/`.
- Run: `xcodegen generate`, `xcodebuild build-for-testing -scheme DeckHandiOS -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath ~/Developer/DeckHand-build/.derived`, then `TEST_RUNNER_PH_QA_OUT=… xcodebuild test-without-building -xctestrun <…>.xctestrun -destination … -only-testing:PixelHandUITests`. `TEST_RUNNER_PH_QA_FREE=1` runs on the free plan; `simctl ui <dev> appearance dark` and `content_size accessibility-extra-large` set the other bands.
- Identifiers added for the walk: `ph.settings.developerUnlock` (Settings › Subscription › Unlock Pro for testing) and `ph.ask.field` (the Ask text field).
- **Simulators can't reach a Mac on the same machine with build 18 (VQ-001).** To capture anything past the picker I used a local, never-committed Mac build with loopback treated as local, only to pair the simulators (`PH_QA_PAIRCODE_FILE` lets the walk type the Mac's code). Paired simulators then connect to the real build 18 without a prompt, and every later capture used `/Applications/Pixel Hand.app`. iPhone 17 Pro, iPhone 17 and iPad Pro 11" are paired with this Mac now.
- Typing and clicks from the walk land on the Mac's front app. Put a scratch document in front first (the QA script opens a TextEdit window and parks the pointer on it).

## Not tested, and why

- **Simulators reaching the Mac at all (VQ-001):** Build 18's Mac refuses every unpaired loopback connection, so no simulator could connect. To get past it I built a local, never-committed Mac build that treats loopback as local, used it only to pair the simulators (and for the iPad mini captures), then went back to /Applications/Pixel Hand.app (build 18) for everything else. Paired simulators connect to the real build without a prompt.
- **iPhone 17 Pro Max, iPad mini automated runs:** The XCTest runner never launched on those two simulators (it hung before the first test for 10+ minutes, twice). The iPad mini was captured by hand; the Pro Max wasn't captured.
- **App Shortcuts and Siri phrases:** Widgets, the Lock Screen widget and the three Control Center controls are covered now (second pass, iPad Pro 11). Shortcuts and Siri weren't driven.
- **Tapping a widget key or the Mission Control control:** They run on the owner's Mac; left for the hands-on walkthrough on the real iPad.
- **The real iPad (iPad Air 11-inch M3):** Xcode lists it as unavailable (locked, asleep or not on the network). Once it's unlocked and reachable, the same UI tests can run on it.
- **Sharing: Share extension, transfers, accepting, clipboard sync:** Needs content in another app and a second device; not exercised.
- **Real gestures (two/three-finger scroll, drag, pinch on the pad), Pencil hover, haptics:** Need real fingers or hardware; the simulator can't drive multi-touch on the pad.
- **Accessibility off, “needs update”, and the capture sheet's “Mac is locked”:** Would mean revoking permissions or installing an old build on the owner's Mac. The shell's locked state was captured when this Mac auto-locked (VQ-068); after that the Mac stayed locked, which ended the Mac-side captures and the iPad dark and iPhone 17 runs.
- **Second Mac (switching, free-tier one-Mac rule against a second Mac):** Only one Mac host exists here.
- **Running a deck key, multi-step keys, Suggest a deck, running an Ask plan:** The deck is empty and running actions would drive the owner's Mac; plans were created but not run. The Suggest button wasn't found on iPhone.
- **PiP window on the Home Screen:** The PiP button isn't in the mirror toolbar unless the setting is on (VQ-060).
- **Region/window capture, OCR, annotation:** The capture button only takes full-screen shots (VQ-052); the region flow wasn't reachable from the walk.
- **Reduce Motion:** The simulator can't toggle Reduce Motion from the command line here; not verified.
- **Wi-Fi off / network loss:** The simulator shares the Mac's network; covered only by quitting the Mac app mid-session (VQ-027).
- **iPad Split View / Slide Over:** Covered by Stage Manager windows at iPhone width and medium width instead (second pass).
